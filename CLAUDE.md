# kid-llm — project rules

A private AI chat for one 10-year-old on her iPhone, in Hebrew. Static PWA on Vercel; no server, no database.

## Git workflow

- Every change gets its own branch from `main`, named `<type>/<short-description>` (`feat`, `fix`, `chore`, `docs`, `test`). Why: `main` is what gets deployed.
- Never commit directly to `main`; push the branch and open a pull request. Only the owner merges, after CI is green. (The only exception was the first commit, which created `main`.)
- Run `npm run lint`, `npm run typecheck` and `npm run test:coverage` before pushing. If `npm install` can't run locally, push anyway and let CI check.
- CI must be green: audit of the shipped libraries, lint, typecheck, unit tests with coverage (thresholds in `vite.config.ts`: 80% lines, statements and functions, 75% branches; 90% and 80% for `src/ai/`), build, and Playwright tests in WebKit at iPhone sizes (`e2e/`). New code arrives with its tests.
- Commit `package-lock.json` with every dependency change. If `npm install` can't run locally, push the `package.json` change to the branch: the "Update lockfile" workflow commits the lockfile there and reruns CI (never on `main`).
- Open pull requests as drafts. After every push of a pull request, a code review agent reviews it for security and for personal data (PII): where her chats, her name and the API key are stored, sent or logged. It posts its verdict and findings as a review on the pull request itself. Fix findings as new commits; never force-push. Then post one comment that lists every finding with the commit that fixed it, or why it is left to the owner.
- Deployment is Vercel's Git integration: every pull request gets a preview deployment, and `main` is production. `vercel.json` holds the build settings and the security headers; there is no deploy workflow and no deploy secret in this repository.

## Platform decisions

| Rule | Why |
|---|---|
| No server. The phone calls the AI provider directly | Nothing is saved on the website; the parent's key and her chats never pass through us |
| Chats are saved only on the phone | Privacy is the reason this app exists |
| The API key is kept apart from chats and is never in a backup | A backup gets shared; a key costs money |
| Hebrew, right to left; text ≥ 15 px, body 17 px; touch targets ≥ 48 px; inputs ≥ 16 px | It's for the kid; smaller inputs make Safari zoom |
| Maths, code, links and numbers with units are always left to right inside Hebrew text | Otherwise "3 + 5 = 8" and minus signs change order |
| She picks modes (שיחה, חיפוש, חשבון, ציור); the parent maps each mode to a model. The model's name is shown, to her and to a parent alike, by the name it is called with (`deepseek-4-1`): under each mode in the mode picker, next to the mode button where she writes, under each answer, and in the list of chats (the model of the chat's newest answer). An answer keeps the name of the model that wrote it (`model` on the message, `src/core/chat.ts`), also when that was the model for files; answers kept before that show none. A stored name is checked before it is shown, and is never sent to a model | The owner chose to show the names so she gets to know the models, and so a parent sees which model a message goes to and which one answered |
| The parent area can load the provider's list of models (`GET /models`; the call carries the key and nothing else) and pick each mode's model from it, narrowed by typing part of a name; a name can still be typed by hand. Offline models are left out; search is offered only models that search the web, drawing only image models, attached files only models that read pictures. Each model shows the provider's tags (private or anonymized, uncensored, TEE, E2EE) and its price in USD for a million tokens, cache included. The list is cleaned before it is shown (`src/ai/models.ts`) and is never stored. An uncensored model is offered only while the "used by a child" box is unticked, and it never answers a child: every call takes its model from `modelFor` / `fileModelFor` (`src/storage/settings.ts`), which give none for an uncensored model while the box is ticked, so that mode counts as not set up. A model is uncensored by the provider's mark, saved with the choice, or by a name that says "uncensored" or "abliterated"; a name typed by hand is matched to the list in any letter case, and one the loaded list doesn't know is shown with a warning, since only its name can be checked. Drawing keeps safe mode either way | The owner chose to allow uncensored models for a parent's own use (#18); her messages never reach one, and the parent sees what a model costs and who sees the text |
| The kid never sees provider messages or error codes; the parent area does | "משהו לא עובד" is enough for her |
| Parent area behind a PIN: provider, key, model per mode, the two system prompts, limits, backup, delete all | She can't change what keeps her safe |
| She can't delete a chat: only "delete all" in the parent area removes chats. Her own messages are always kept; "try again" still replaces the last answer | A parent can always see what she asked (#15, #22) |
| Image requests always go with the provider's safe mode on and the fixed child-safety line. A picture is shown only when the provider's two safety headers both say it is fine; marked, or with a header missing, it is a refusal and is never shown | It's a kid's app, so a check that can't be made counts as failed |
| A picture request carries only what she wrote for that picture. Pictures are kept as bytes with their chat, on the phone only, and are left out of what chat models are sent | The provider learns no more than it needs, and a picture can't be sent as text |
| Search mode asks the provider to search the web (`enable_web_search: on`); no other mode does. A search call carries only what she wrote in search mode, and the search lines of `src/ai/baseline.ts`. "Try again" asks in the mode her message was written in. The parent area says that what she writes in search mode also reaches a search engine | She gets what she picked, what she said elsewhere stays out of a search engine, and the parent knows what leaves the phone |
| Under a search answer the app shows up to 5 links to the sites it came from, taken from the provider's list of sources: https only on the usual port, an ordinary site name (never a number address), one per site, shown by the site's name, never the page's title or text. They open outside the app with no referrer; the parent area says that nothing but the iPhone's Screen Time filters those sites. The model's own text never becomes a link for her. Only in a parent's own use does an address the model wrote (bare or `[label](address)`) become a link, with the same checks, shown by its site's name next to the label, never the label alone | The owner chose links (#21), and links in a parent's own use; a page's title and text pass no child-safety check, and a link the model wrote could point anywhere, so a label can't hide the site |
| While the parent area's "the app is used by a child" box is ticked, every chat call starts with the built-in instructions in `src/ai/baseline.ts`; the system prompt the parent wrote for her is added after them, never instead. The box is ticked by default, and anything missing or unreadable in the saved settings counts as ticked. A parent can untick it, behind the code, to use the app themself: then only the system prompt the parent wrote for a parent is sent (with today's date, and the lines about not following instructions found in web text or in a file), the parent area shows a warning, and the chat screen says "מצב הורים" for as long as it lasts; it does not end by itself (the owner's choice). A chat started in a parent's own use is saved on the phone like hers, marked as the parent's (`parentUse` on the chat, `src/core/chat.ts`): it is in the list of chats, marked "הורים", and can be opened only while the app is in a parent's own use, where the list shows her chats too. In her use it is in no list and can't be opened. What a parent adds to one of her chats is not saved, and when the app changes hands the chat on the screen is replaced by a new one, so her list of chats holds only answers written with the child instructions. "Delete all" removes the parent's chats too; the parent's chats are stored as plainly as hers, kept from her by the app and the code, not by encryption. Drawing keeps safe mode and the child-safety line either way. The parent area shows the built-in instructions word for word | Her messages never reach a model with no instructions; the owner chose a switch so a parent can use the app as an adult (#36), and a phone left that way is noticed; the owner chose to keep a parent's own chats, seen only in a parent's own use |
| The parent writes two system prompts, kept in two fields of the settings: one for her (`systemPrompt`) and one for a parent's own use (`parentSystemPrompt`). A call carries exactly one of them: hers with the child baseline, a parent's only in a parent's own use. Neither fills in for the other when it is empty, and settings saved before there were two count as hers, with nothing written for a parent. Every chat call takes its written text from `instructionsFor` (`src/storage/settings.ts`), and `sendChat` picks the text by the same switch that picks the baseline, so a call that was handed both still sends one. The parent area shows them through one list ("לילדה" / "להורים") and one text box, and says where each one goes | What a parent writes for themself (an adult's tone, an adult's topics) must never steer an answer to her, and what is written about her has no place in a parent's own call |
| Every chat call carries today's date and weekday, from the phone's clock, always in Israel time (`Asia/Jerusalem`), in English with the month as a name and as a number: "Today is Sunday, 15 November 2026 (day 15, month 11, year 2026), Israel time." (`dateLineFor`, `src/ai/baseline.ts`). It closes the built-in lines, before the parent's instructions, for a child and in a parent's own use; a picture request carries no date. The parent area shows the line as it is sent | A model has no clock, and the provider's own system prompt is switched off, so it took "today" from its training or from a web page a search found; a month written as a name and a number can't be read as dd/mm or mm/dd |
| A model the provider's list tags `supportsE2EE` (saved with the choice, like the uncensored mark; never guessed from the name, since Venice gives TEE and E2EE the same model name) gets end-to-end encrypted chat calls (`src/ai/e2ee.ts`), as Venice's guide describes: a key pair for each call, wiped after; the enclave's attestation asked for with a fresh 32-byte nonce and checked first (Venice's own verdict, the nonce, the model, a TDX quote that is not in debug mode, a valid model key; then, on the phone and not on Venice's word, that Intel hardware signed the quote, `src/ai/tdxQuote.ts`: the certificate chain to Intel's root key pinned in `src/ai/intelRoot.ts`, Intel's quoting enclave, the quote's signature; and that the quote's REPORTDATA holds the model key's address and this call's nonce); every system and user message encrypted; the three `X-Venice-TEE-*` headers; every piece of the answer decrypted. It fails closed: an attestation that doesn't pass sends nothing of hers, and a plain or undecryptable piece ends the answer. Earlier answers are sent as they are (the docs encrypt only system and user messages). Search calls and calls with a file go as ordinary calls even to such a model, since Venice disables web search and takes no files with E2EE. Not checked yet, and the parent area says so: which software runs in the enclave (the quote's measurements), whether the processor's firmware is up to date or its certificate revoked (Intel's TCB info and CRLs, which would need a call to Intel or a third party for every check), the NVIDIA GPU evidence, response signatures. So a provider that runs other software on a real Intel TDX machine still passes. The quote's four signatures are checked by the browser's own cryptography (WebCrypto), since a P-256 check in JavaScript is slow enough on an iPhone to delay every answer; hashing uses the pinned `@noble` libraries; the verifier makes no network call. Anonymized, private and TEE models all get the same ordinary call | Venice relays only ciphertext for her messages, a key that no Intel TDX machine vouched for or a quote made for another call is refused, and a check that can't be made counts as failed; the parent area says what E2EE covers and what it does not |
| An `AiError`'s `detail` is for the parent area's screen only: never stored, backed up or logged | A provider may quote part of her message in it |
| Provider calls go through one module that applies the timeout, redacts the key from errors and maps failures to reasons | One place enforces privacy and limits; a new provider only describes its request and response |
| Security headers live in `vercel.json`; the CSP's `connect-src` lists exactly the provider endpoints the app calls | Even a compromised dependency can't send her chats anywhere else |
| `.npmrc` sets `ignore-scripts=true`; libraries that ship inside the app are pinned to exact versions; GitHub Actions are pinned to commit SHAs | A hijacked package or a moved tag can't change what runs |
| Colours only through the tokens in `src/styles.css` | One place to keep contrast readable |
| An answer cut because the app left the screen (iOS stops a web app there, and with no server nothing can keep the call going) is asked for again by the app once she is back: the same messages, in the mode her message was written in, up to 3 times per message, free of the daily count, never after her "עצירה", never once the app changed hands (a parent's own use switched on or off), and never for a failure that isn't a cut connection or a timeout. It goes with the settings and the key as they are then. In search mode that sends her question to the search engine again. When the app leaves the screen, what was written so far is saved, marked as cut (in a parent's own use too, into the parent's own chat; never what a parent adds to one of her chats) | She gets no error for switching apps, and a half answer survives the phone closing the app (#33) |
| The parent area ends with the build's version: the short commit and its date, put in at build time, linking to that commit on GitHub. Only there, behind the code; the link is built from a 40-character commit name and nothing else | A parent can tell whether a fix has reached the phone (#35); she gets no link out of the app |
| She can attach one file to a message (a picture, a PDF or a Word file) only in שיחה and חשבון, and only once the parent chose a model for files; never in search or drawing. What a file is comes from its first bytes. A picture is redrawn on the phone into a smaller JPEG, so its hidden data (location, date, phone) never leaves; a document goes as it is, under a fixed name, never her file name. Only the newest file in a chat is sent again with later messages, and not at all once the provider refused it. Files are kept with their chat, on the phone only. The parent area says what leaves the phone | A photo can show her face and a file name can hold her name; the provider gets what the answer needs and no more (#17) |
| Backup is one file of every chat on the phone, hers and a parent's own, with their pictures and files (`src/core/backup.ts`, `src/storage/backup.ts`): a head line (`kid-llm backup 1`), then each chat as its JSON followed by its pictures' and files' raw bytes, read and written one chat at a time. Only the chat store is read and written: never the key, the code or the settings. Every chat goes through `sanitizeChat` on the way out and on the way in. Importing only adds: a chat whose id is already on the phone is left as it is, and nothing is deleted. A file that doesn't start with the head line is refused; one cut short or damaged keeps the chats before that point and says so. The file is not encrypted, and the parent area says so. It leaves through the share sheet where the phone shares files (a home-screen app on iOS can't download), and is downloaded elsewhere; making it and handing it over are two taps, since Safari opens the share sheet only straight from a tap | A backup gets shared, so it carries chats and nothing that costs money or opens the settings; pictures as bytes keep the file small and the phone's memory free; an import can't overwrite or remove what is on the phone (#20) |
