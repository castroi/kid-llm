# kid-llm — project rules

A private AI chat for one 10-year-old on her iPhone, in Hebrew. Static PWA on Vercel; no server, no database.

## Git workflow

- Every change gets its own branch from `main`, named `<type>/<short-description>` (`feat`, `fix`, `chore`, `docs`, `test`). Why: `main` is what gets deployed.
- Never commit directly to `main`; push the branch and open a pull request. Only the owner merges, after CI is green. (The only exception was the first commit, which created `main`.)
- Run `npm run lint`, `npm run typecheck` and `npm run test:coverage` before pushing. If `npm install` can't run locally, push anyway and let CI check.
- CI must be green: audit of the shipped libraries, lint, typecheck, unit tests with coverage (thresholds in `vite.config.ts`: 80% lines, statements and functions, 75% branches; 90% and 80% for `src/ai/`), build, and Playwright tests in WebKit at iPhone sizes (`e2e/`). New code arrives with its tests.
- Commit `package-lock.json` with every dependency change. If `npm install` can't run locally, push the `package.json` change to the branch: the "Update lockfile" workflow commits the lockfile there and reruns CI (never on `main`).
- Open pull requests as drafts. After every push of a pull request, a code review agent reviews it for security and for personal data (PII): where her chats, her name and the API key are stored, sent or logged. It posts its verdict and findings as a review on the pull request itself. Fix findings as new commits; never force-push. Then post one comment that lists every finding with the commit that fixed it, or why it is left to the owner.
- Deployment is Vercel's Git integration: every pull request gets a preview deployment, and `main` is production. `vercel.json` holds the build settings and the security headers; there is no deploy workflow and no deploy secret in this repository.

## Platform decisions

| Rule | Why |
|---|---|
| No server. The phone calls the AI provider directly | Nothing is saved on the website; the parent's key and her chats never pass through us |
| Chats are saved only on the phone | Privacy is the reason this app exists |
| The API key is kept apart from chats and is never in a backup | A backup gets shared; a key costs money |
| Hebrew, right to left; text ≥ 15 px, body 17 px; touch targets ≥ 48 px; inputs ≥ 16 px | It's for the kid; smaller inputs make Safari zoom |
| Maths, code, links and numbers with units are always left to right inside Hebrew text | Otherwise "3 + 5 = 8" and minus signs change order |
| She sees modes (שיחה, חיפוש, חשבון, ציור), never model names; the parent maps each mode to a model | She shouldn't have to know what a model is |
| The parent area can load the provider's list of models (`GET /models`; the call carries the key and nothing else) and pick each mode's model from it, narrowed by typing part of a name; a name can still be typed by hand. Offline models are left out; search is offered only models that search the web, drawing only image models, attached files only models that read pictures. Each model shows the provider's tags (private or anonymized, uncensored, TEE, E2EE) and its price in USD for a million tokens, cache included. The list is cleaned before it is shown (`src/ai/models.ts`) and is never stored. An uncensored model is offered only while the "used by a child" box is unticked, and it never answers a child: every call takes its model from `modelFor` / `fileModelFor` (`src/storage/settings.ts`), which give none for an uncensored model while the box is ticked, so that mode counts as not set up. A model is uncensored by the provider's mark, saved with the choice, or by a name that says "uncensored" or "abliterated"; a name typed by hand is matched to the list in any letter case, and one the loaded list doesn't know is shown with a warning, since only its name can be checked. Drawing keeps safe mode either way | The owner chose to allow uncensored models for a parent's own use (#18); her messages never reach one, and the parent sees what a model costs and who sees the text |
| The kid never sees provider messages or error codes; the parent area does | "משהו לא עובד" is enough for her |
| Parent area behind a PIN: provider, key, model per mode, system prompt, limits, backup, delete all | She can't change what keeps her safe |
| She can't delete a chat: only "delete all" in the parent area removes chats. Her own messages are always kept; "try again" still replaces the last answer | A parent can always see what she asked (#15, #22) |
| Image requests always go with the provider's safe mode on and the fixed child-safety line. A picture is shown only when the provider's two safety headers both say it is fine; marked, or with a header missing, it is a refusal and is never shown | It's a kid's app, so a check that can't be made counts as failed |
| A picture request carries only what she wrote for that picture. Pictures are kept as bytes with their chat, on the phone only, and are left out of what chat models are sent | The provider learns no more than it needs, and a picture can't be sent as text |
| Search mode asks the provider to search the web (`enable_web_search: on`); no other mode does. A search call carries only what she wrote in search mode, and the search lines of `src/ai/baseline.ts`. "Try again" asks in the mode her message was written in. The parent area says that what she writes in search mode also reaches a search engine | She gets what she picked, what she said elsewhere stays out of a search engine, and the parent knows what leaves the phone |
| Under a search answer the app shows up to 5 links to the sites it came from, taken from the provider's list of sources: https only on the usual port, an ordinary site name (never a number address), one per site, shown by the site's name, never the page's title or text. They open outside the app with no referrer; the parent area says that nothing but the iPhone's Screen Time filters those sites. The model's own text never becomes a link for her. Only in a parent's own use does an address the model wrote (bare or `[label](address)`) become a link, with the same checks, shown by its site's name next to the label, never the label alone | The owner chose links (#21), and links in a parent's own use; a page's title and text pass no child-safety check, and a link the model wrote could point anywhere, so a label can't hide the site |
| While the parent area's "the app is used by a child" box is ticked, every chat call starts with the built-in instructions in `src/ai/baseline.ts`; the parent's system prompt is added after them, never instead. The box is ticked by default, and anything missing or unreadable in the saved settings counts as ticked. A parent can untick it, behind the code, to use the app themself: then only the parent's own instructions are sent (with the lines about not following instructions found in web text or in a file), the parent area shows a warning, and the chat screen says "מצב הורים" for as long as it lasts; it does not end by itself (the owner's choice). A chat in a parent's own use is never saved on the phone, and when the app changes hands the chat on the screen is replaced by a new one, so her list of chats holds only answers written with the child instructions. Drawing keeps safe mode and the child-safety line either way. The parent area shows the built-in instructions word for word | Her messages never reach a model with no instructions; the owner chose a switch so a parent can use the app as an adult (#36), and a phone left that way is noticed |
| An `AiError`'s `detail` is for the parent area's screen only: never stored, backed up or logged | A provider may quote part of her message in it |
| Provider calls go through one module that applies the timeout, redacts the key from errors and maps failures to reasons | One place enforces privacy and limits; a new provider only describes its request and response |
| Security headers live in `vercel.json`; the CSP's `connect-src` lists exactly the provider endpoints the app calls | Even a compromised dependency can't send her chats anywhere else |
| `.npmrc` sets `ignore-scripts=true`; libraries that ship inside the app are pinned to exact versions; GitHub Actions are pinned to commit SHAs | A hijacked package or a moved tag can't change what runs |
| Colours only through the tokens in `src/styles.css` | One place to keep contrast readable |
| An answer cut because the app left the screen (iOS stops a web app there, and with no server nothing can keep the call going) is asked for again by the app once she is back: the same messages, in the mode her message was written in, up to 3 times per message, free of the daily count, never after her "עצירה", never once the app changed hands (a parent's own use switched on or off), and never for a failure that isn't a cut connection or a timeout. It goes with the settings and the key as they are then. In search mode that sends her question to the search engine again. When the app leaves the screen, what was written so far is saved, marked as cut (never in a parent's own use, whose chats are not saved) | She gets no error for switching apps, and a half answer survives the phone closing the app (#33) |
| The parent area ends with the build's version: the short commit and its date, put in at build time, linking to that commit on GitHub. Only there, behind the code; the link is built from a 40-character commit name and nothing else | A parent can tell whether a fix has reached the phone (#35); she gets no link out of the app |
| She can attach one file to a message (a picture, a PDF or a Word file) only in שיחה and חשבון, and only once the parent chose a model for files; never in search or drawing. What a file is comes from its first bytes. A picture is redrawn on the phone into a smaller JPEG, so its hidden data (location, date, phone) never leaves; a document goes as it is, under a fixed name, never her file name. Only the newest file in a chat is sent again with later messages, and not at all once the provider refused it. Files are kept with their chat, on the phone only. The parent area says what leaves the phone | A photo can show her face and a file name can hold her name; the provider gets what the answer needs and no more (#17) |
